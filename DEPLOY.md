# Deploying to Render

This repo has a `render.yaml` Blueprint that deploys both services in one go.
I can't click through your Render dashboard for you (no account access from
here), but everything the code needs is already in place — these are the
steps to finish it on your side.

## 1. Push this repo to GitHub

Render deploys from a GitHub repo, so `Sriainfotech/expense-tracker` needs to
have these commits pushed first (currently blocked on a permissions issue —
see the earlier note about `Saf-reen` needing write access).

## 2. Create the Blueprint

1. Go to the [Render Dashboard](https://dashboard.render.com/) → **New** → **Blueprint**.
2. Connect/select the `Sriainfotech/expense-tracker` repo.
3. Render reads `render.yaml` and proposes two services:
   - `expense-tracker-backend` (Django API, Python)
   - `expense-tracker-frontend` (TanStack Start app, Node)
4. Click **Apply**.

## 3. Set the one secret Render will ask for



Render will prompt for any env var marked `sync: false` in `render.yaml`:

- **`expense-tracker-backend` → `DATABASE_URL`**: paste your Neon connection
  string (the same one already in `Expense-Backend/.env` locally), e.g.
  `postgresql://user:password@host.neon.tech/dbname?sslmode=require`.

Nothing else needs to be typed in — `DJANGO_SECRET_KEY` is auto-generated by
Render, and the rest are already set in `render.yaml`.

## 4. Check the actual URLs Render assigned

Render service names must be globally unique across *all* Render users, so if
`expense-tracker-backend` or `expense-tracker-frontend` are already taken,
Render will give you different hostnames than the ones baked into
`render.yaml` (`DJANGO_ALLOWED_HOSTS`, `EXTRA_ALLOWED_ORIGINS`,
`VITE_API_BASE_URL`).

After the first deploy, open each service's page and confirm its URL matches
what's in `render.yaml`. If Render changed a name:

1. Open **expense-tracker-backend → Environment** and update:
   - `DJANGO_ALLOWED_HOSTS` → the backend's actual `*.onrender.com` host
   - `EXTRA_ALLOWED_ORIGINS` → the frontend's actual URL (with `https://`)
2. Open **expense-tracker-frontend → Environment** and update:
   - `VITE_API_BASE_URL` → `https://<actual-backend-host>/api`
3. Manually redeploy both services (env var changes don't auto-rebuild the
   frontend, since `VITE_API_BASE_URL` gets baked in at build time).

## 5. Seed demo data (optional, one-time)

From the backend service's **Shell** tab in Render:

```
python seed_demo.py
```

This creates the demo admin/user accounts and default expense categories —
skip it if you already seeded the same Neon database locally.

## Notes

- Both services are on the **free plan** — they spin down after inactivity
  and take ~30-60s to wake up on the next request. Upgrade the plan in
  Render if that's a problem.
- The frontend build pins `NITRO_PRESET=node-server` so it runs as a plain
  Node server (Render, not Cloudflare) — see the comment in
  `Expense-Tracker/vite.config.ts` for why that's an env var and not a code
  change.
- Static admin assets are served via WhiteNoise, so Django's admin panel
  works even with `DEBUG=False`.
